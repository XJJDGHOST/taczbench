# TaCZ Bench · 永恒枪械工坊调校台

给 **Minecraft 1.20.1 + Forge + 永恒枪械工坊（TaCZ）** 做的枪械数据调校模组。
在游戏里开一个界面，拖滑条改枪的伤害 / 射速 / 后坐 / 散布 / 弹匣 / 重量……改完点一下，
覆盖数据包写进存档，**不动原枪包一行代码**，随时可以整体还原。

![界面设计稿](docs/ui-mockup.png)

> 上图是按 `WorkshopScreen.java` 里的布局常量和配色画的设计稿，不是游戏内截图（见文末「验证情况」）。

## 1. 它解决什么问题

现在改 TaCZ 枪械数值的标准流程（[mcmod 教程](https://www.mcmod.cn/post/4946.html)）是：

1. 找到 `.minecraft/tacz/xxx.zip`
2. 解压 / 用压缩软件打开
3. 在 `data/<命名空间>/data/guns/` 里翻到那把枪的 json
4. 用记事本改数字 —— 字段名全靠注释认，改错一个逗号整个枪包加载失败
5. 想加个枪口 / 枪托插槽？还要再去 `tacz_tags/attachments/allow_attachments/` 改另一个文件
6. 保存、重开游戏、进游戏试、不满意再回到第 2 步
7. 想换回原版？没备份就只能重下枪包

这个模组把第 2～7 步变成一个界面里的滑条：

- **不用解压**：直接读 `tacz/` 下的 zip、文件夹、`mods/` 里的枪包 jar、数据包形式的枪包
- **不用查字段名**：内置 40 多个常用字段的中文名、范围、单位、说明；没收录的字段也会按实际类型自动列在「其它字段」里
- **不会改坏**：改的是内存里的值，只在你点「应用」时才落盘，而且写的是**另一个**覆盖数据包
- **能反悔**：每把枪一键撤销；整个覆盖层删掉就 100% 回原版
- **看得见后果**：界面顶部实时算单发伤害、爆头伤害、DPS、打空弹匣耗时、TTK

## 2. 三个核心设计

### 2.1 零侵入：不碰 TaCZ 的类，也不碰枪包

模组**不 import 任何 `com.tacz.*` 类**，也不用 Mixin。它只认一件事：TaCZ 的枪械数据是
`data/<命名空间>/data/guns/*.json` 这样的 JSON 文件。

这意味着兼容性不依赖 TaCZ 内部实现：

| 情况 | 是否可用 |
|---|---|
| TaCZ 1.1.x | 可用（数据格式一致） |
| TaCZ 1.2.0 | 可用（默认枪包就是按这个格式放的） |
| 枪包放 `tacz/xxx.zip` | 可用 |
| 枪包放 `tacz/xxx/`（文件夹） | 可用 |
| 枪包做成 `mods/xxx.jar`（PBK 那套） | 可用 |
| 枪包做成数据包放存档 | 可用 |
| 和别的改枪模组同时装 | 不冲突（不抢类、不抢文件） |

### 2.2 覆盖数据包：改动可逆

点「应用并重载」后，模组把改动过的文件写成：

```
saves/<存档>/datapacks/taczbench_overlay/
├── pack.mcmeta
└── data/tacz/data/guns/ak47_data.json
```

然后自动启用这个数据包并触发一次 `/reload`。原版数据包的优先级高于 mod 自带的资源，
所以覆盖生效；而**原枪包文件一个字节都没动**。

想全部还原：删掉 `taczbench_overlay` 文件夹就行（界面上也有「全部还原」按钮）。

### 2.3 只改值，保留注释

TaCZ 的数据文件里全是这种中文注释：

```jsonc
{
  // 弹容
  "ammo_amount": 30,
  // 每分钟射出弹药量，最大不应超过 1200
  "rpm": 600,
```

用 Gson 解析再序列化，这些注释会全部消失——以后想手改就没得看了。
所以这个模组自己写了一个带位置信息的 JSON5 解析器（`JsonDoc`），
改值时**只替换目标数字所在的字符区间**，其余文本原样保留：

```
改之前：  "rpm": 600,
改之后：  "rpm": 750,
注释、缩进、空行、字段顺序 —— 全都没变。
```

## 3. 界面怎么用

默认按 **K** 打开（可在「选项 → 控制 → 按键绑定 → TaCZ 调校台」里改）。

- **左栏**：搜索框 + 「枪械 / 配件」两页签 + 列表。改过的枪右侧有个橙色小点。
- **中栏**：
  - 顶部是 5 个实时指标（单发 / 爆头 / DPS / 打空弹匣 / 击杀 20 血耗时）
  - 下面按「伤害与弹道 / 射速与动作 / 散布与后坐 / 弹匣与换弹 / 重量与移速」分组
  - **拖滑条**改值；**点数值**可以直接输入精确值；**Shift + 拖**是微调；改过的行变橙色，右边有 `×` 单独还原
  - 文件里没写、但 TaCZ 支持的可选字段（比如 `bolt_action_time`）也会列出来，设了就会新增
- **右栏**：应用并重载 / 撤销本枪改动 / 全部还原 / 重新扫描枪包

服务端也能用（不进游戏界面）：

```
/taczbench list       列出扫到的枪械
/taczbench applied    看覆盖层写了哪些文件
/taczbench rescan     重新扫描枪包（需要 OP）
```

## 4. 编译

这个模组需要 Forge 1.20.1 的开发环境。两种方式：

### 方式 A：GitHub Actions（不用装 JDK）

仓库里已经带好了 `.github/workflows/build.yml`，push 上去后
在 Actions 里下载 `taczbench-jar` 就能拿到 `build/libs/taczbench-1.20.1-1.0.0.jar`。

### 方式 B：本地构建

需要 **JDK 17**（JDK 21 也可以，Gradle 会按 17 的字节码编译）：

```bash
gradle build          # 没有 wrapper，直接用本机 gradle 8.x
# 产物：build/libs/taczbench-1.20.1-1.0.0.jar
```

装进 `mods/`，**不需要**装在前置里（`mods.toml` 里没写死 TACZ 依赖，但不装 TACZ 就没数据可调）。

## 5. 外置调校台（不用编译，现在就能用）

`tools/` 里是一个浏览器版调校台，走的是**同一套改写引擎**（`writer.jar` 就是 `core` 打包的），
所以它改出来的文件和模组界面的结果一致：只替换数字、注释排版原样保留、每次保存自动留 `.bak`。

```bat
tools\启动调校台.bat
```

会打开 `http://127.0.0.1:8765/`：

- 自动找到 PCL / 官方启动器的 `.minecraft`，扫 `tacz/` 下所有枪包（zip 和文件夹都行）
- 左边搜枪（显示中文名），中间拖滑条，顶部实时算 DPS / TTK
- 点「保存到枪包」→ 写回并生成 `.bak-时间戳`
- 改完回游戏里**退出存档再进**即生效（TACZ 进世界时会重新扫 `tacz/`）

前提：机器上要有 JDK（用游戏自带的 `java-runtime-delta` 就行，脚本里已经指好）。

## 6. 项目结构

```
src/main/java/com/taczbench/
├── TaczBench.java              模组入口 + 命令注册
├── WorkshopService.java        桥接层：找游戏目录 / 存档 / 写覆盖层 / 触发 reload
├── command/WorkshopCommand.java
├── client/
│   ├── TaczBenchClient.java    按键注册
│   ├── ClientEvents.java       按键 → 开界面
│   ├── Ui.java                 配色 + 绘制小工具（无贴图，纯色块）
│   └── WorkshopScreen.java     主界面（约 800 行）
└── core/                       ← 不依赖 Minecraft，可以单独跑测试
    ├── JsonDoc.java            带注释保留的 JSON5 解析 / 精准改写
    ├── JsonNode.java           带源码下标的节点
    ├── Path.java               点分路径
    ├── FieldSpec.java          一个字段的描述
    ├── Schema.java             字段方案（可被 config/taczbench/schema.json 覆盖）
    ├── GunEntry.java           一个枪械数据文件
    ├── WorkshopRepository.java 枪包扫描（zip / 文件夹 / jar / 数据包）
    ├── OverlayWriter.java      覆盖数据包写入
    └── Stats.java              DPS / TTK 计算
```

字段方案第一次启动会导出到 `config/taczbench/schema.json`。
想改界面上的名字、范围，或者 TaCZ 以后加了新字段，直接改这个文件，**不用重新编译模组**。

## 7. 验证情况（重要，请先看这段）

拆成两层，分别验证：

**数据层 `core`：已实测通过 68 项断言。**
用的是 TaCZ 官方仓库里的真实文件
[`ak47_data.json`](https://github.com/MCModderAnchor/TACZ)（13 KB，带全部中文注释）当样本：

- 解析：28 个顶层字段、嵌套对象、数组、数组里套对象、`"infinite"` 这种字符串混在数字字段里
- 改写：改 5 个字段后，其余字段、数组、注释、行数全部不变；同值重写文本完全相同（幂等）
- 插入：`recoil_push` 这种原本被注释掉、文件里不存在的字段可以正确插入
- 报错：坏 JSON 能报出准确行号
- 扫描：文件夹方式和 zip 方式都能扫到枪械 / 配件，能读到本地化键和类型
- 覆盖层：写入 / 幂等 / 清理 / 目录穿越防护
- 端到端：扫描 → 改数值 → 写覆盖层 → 重读校验，DPS 跟着变

跑法：

```powershell
powershell -ExecutionPolicy Bypass -File verify\run.ps1
```

**界面层：做到了「能编译」，但没有在游戏里跑过。**
我没有这台机器上的 Forge 开发环境（到 Forge 官方 maven 的下载速度只有约 40 KB/s，
拉不动 200+ MB 的依赖），所以给 Minecraft / Forge 的 API 写了一组**类型桩**，
用 `javac --release 17` 把整个模组编译了一遍（0 错误），用来抓拼写、签名、类型错误。
这能保证「代码不会一编译就炸」，但**不能替代进游戏实测**。

所以第一次进游戏时请留意：

- 按 K 能不能打开界面
- 列表里有没有扫到枪（没有就点「重新扫描枪包」）
- 改一个数值 → 应用 → 枪的手感 / 数据有没有真的变
- 删掉 `saves/<存档>/datapacks/taczbench_overlay` 后是否恢复原样

有任何报错，把 `logs/latest.log` 里带 `taczbench` 的部分发我，我按日志改。

## 8. 已知限制

- **多人游戏**：数值是服务端数据，覆盖层必须写在服务端（或单机存档）里。
  客户端连别人服务器时，界面能看能算，但点「应用」会提示「还没有进入存档」。
- **应用后要重载**：`/reload` 是异步的，界面上的状态栏会提示「正在重载」。
  重载完成后不需要重开存档，但保险起见可以重进一次世界。
- **只做了枪械 + 配件数据**：弹药（`index/ammo`）、方块（`data/blocks`）、合成配方还没接进界面，
  但扫描和覆盖层机制是通用的，加字段方案就能扩。
- **数组型字段**（`fire_mode`、`allow_attachment_types`、`recoil.pitch` 关键帧）目前是只读展示，
  改它们得用「其它字段」里的原始文本编辑，体验一般。
- **首屏扫描**：打开界面时会扫一遍 `mods/` 下的所有 jar，整合包很大时可能卡 1～2 秒。

## 9. 和 TACZ Workshop 的区别

思路是一样的（用界面代替手改 json），差别在取舍：

| | 这个模组 | 常见做法 |
|---|---|---|
| 改完落在哪 | 独立覆盖数据包，可整包删除 | 直接改枪包文件 / 导出新枪包 |
| 原文件 | 完全不动 | 需要自己备份 |
| 注释 | 保留 | 序列化后丢失 |
| 依赖 TaCZ 内部类 | 不依赖 | 通常要 |
| 换 TaCZ 版本 | 数据格式不变就能用 | 可能要等适配 |
| TaCZ 没装 | 仍可当枪包查看器 | 一般不行 |
